# Promoter：五状态策略生命周期与晋升/降级

> 本文解析 `internal/ares_evolution/promotion/` 的冠军/挑战者晋升系统：`DefaultPromoter`、五状态状态机、`PromotionCriteria` 的 12 个默认参数、`MeetsPromotionCriteria` / `CalculateEvidenceScore`，以及滚动改进与冷却期。所有类型与方法签名都来自真实源码，默认值均为仓库里的常量。

---

## 1. 系统概述

Promoter 用 **Champion/Challenger** 模式决定"候选策略 → 冠军策略"谁能上位。它有五个真实状态（`types.go`）：

```go
const (
    StrategyStateCandidate StrategyState = "candidate"
    StrategyStateShadow    StrategyState = "shadow"
    StrategyStateChampion  StrategyState = "champion"
    StrategyStateDemoted   StrategyState = "demoted"
    StrategyStateRetired   StrategyState = "retired"
)
```

注意：`StrategyState` 是 **string**，不是 int。旧版文章把它画成 `iota` 的 int 枚举——不对（那是另一个包里的风格，promotion 包用的是字符串）。

## 2. 状态转换是显式的有向图

`CanPromoteTo` / `CanDemoteTo` 用显式转换表，且**是 DAG，无环**：

| 转换目标（状态） | 可晋升到 | 可降级到 |
|------------------|----------|----------|
| candidate | shadow | retired |
| shadow | champion | demoted, retired |
| champion | {} | demoted |
| demoted | shadow | retired |
| retired | {} | {} |

实现上 `CanPromoteTo` / `CanDemoteTo` 各自内联一张 `map[StrategyState][]StrategyState`，逐个比对——这正是旧文里"显式双向跳转表"的准确描述，但注意它跟 `PromotionLogic` 接口的 `Promote`/`Demote` 方法是独立的：接口方法做**实际转移**，`CanPromoteTo` 做**校验**。

## 3. PromotionCriteria 与默认值

全部 12 个参数（`types.go`，`json` 标签略）：

```go
type PromotionCriteria struct {
    MinSampleCount         int
    MinSuccessRate         float64
    MaxErrorRate           float64
    MaxLatencyP95          int64
    MinConfidence          float64
    ChampionHoldPeriod     int
    DemotionThreshold      float64
    CoolDownGenerations    int
    MinAbsoluteImprovement float64
    MinRollingImprovement  float64
    ImprovementWindow      int

}

func DefaultPromotionCriteria() *PromotionCriteria {
    return &PromotionCriteria{
        MinSampleCount:         100,
        MinSuccessRate:         0.85,
        MaxErrorRate:           0.15,
        MaxLatencyP95:          5000,
        MinConfidence:          0.7,
        ChampionHoldPeriod:     5,
        DemotionThreshold:      0.3,
        CoolDownGenerations:    3,
        MinAbsoluteImprovement: 0.5,
        MinRollingImprovement:  0.1,
        ImprovementWindow:      3,
        MaxChampionTenure:      20,
    }
}
```

晋升判定（五条全过才算达标）：

```go
func MeetsPromotionCriteria(e experience.Evidence, criteria *PromotionCriteria) bool {
    // SampleCount >= MinSampleCount
    // SuccessRate >= MinSuccessRate
    // ErrorRate <= MaxErrorRate
    // LatencyP95 <= MaxLatencyP95
    // Confidence >= MinConfidence
}
```

加权证据评分（`CalculateEvidenceScore`），真实权重是 0.4 / 0.3 / 0.2 / 0.1：

```go
const (
    successRateWeight = 0.4
    errorRateWeight   = 0.3

// latency 归一化：1.0 - LatencyP95/10000.0，下限 0
```

## 5. 核心流程：Evaluate

`PromotionLogic` 接口的方法签名是真实的：

```go
type PromotionLogic interface {
    Evaluate(ctx context.Context, strategyID string, evidence experience.Evidence) (StrategyState, string, error)
    Promote(ctx context.Context, strategyID string) error
    Demote(ctx context.Context, strategyID string, reason string) error
    GetHistory(ctx context.Context, strategyID string) ([]StrategyPromotionRecord, error)
    GetCurrentState(ctx context.Context, strategyID string) (StrategyState, error)
    GetChampions(ctx context.Context, taskType string) ([]StrategyInfo, error)
    GetStrategyInfo(ctx context.Context, strategyID string) (*StrategyInfo, error)
}
```

（注意：返回的是 `(推荐状态, 原因, error)`，**没有**旧文里的 `Action` 类型。真正的状态转移落在 `Promote`/`Demote`，`Evaluate` 只是返回"建议"。）

`Evaluate` 每次：算分 → 首次创建 `StrategyInfo` → 追加 `ScoreSnapshot`（最多保留 20 条）→ 定期清扫长寿金退役策略（见 §7）→ 首次进 shadow 捕获基线 → 检查冷却期 → 按 `info.CurrentState` 分发到四个 `evaluateXxx`：

### 5.1 candidate → shadow（低门槛，鼓励入场）

```go
if evidence.SampleCount >= 10 && evidence.SuccessRate >= 0.5 {
    return StrategyStateShadow, "promoted to shadow: ..."
}
```

阈值是 **10 样本 + 50% 成功率**。目的：让足够多候选进入影子池竞争，别太早淘汰有潜力的策略。

### 5.2 shadow → champion（最严格）

```go
if MeetsPromotionCriteria(evidence, p.criteria) {
    if info.BaselineScore > 0 {
        scoreDelta := score - info.BaselineScore
        if scoreDelta < p.criteria.MinAbsoluteImprovement {
            return StrategyStateShadow, "blocked: score_delta below min_improvement"
        }
        return StrategyStateChampion, "promoted to champion: ..."
    }
    return StrategyStateChampion, "promoted to champion: ..."
}
// 反向：成功率跌破 MinSuccessRate - DemotionThreshold → demoted
```

即 **达标（五条）+ 相对基线改进 ≥0.5** 才升冠军；同时若退化明显则降级。

### 5.3 champion（三个出口）

1. **数据退化**：`SampleCount` 够且 `SuccessRate < MinSuccessRate-DemotionThreshold || ErrorRate > MaxErrorRate || LatencyP95 > MaxLatencyP95` → **demoted**。
2. **任期安全阀**：`GenerationCount >= MaxChampionTenure(20)` 时看滚动改进，`rolling < MinRollingImprovement(0.1)` → **降回 shadow**（给其他策略机会）；否则**延长任期**。
3. **保持期检查**：`GenerationCount >= ChampionHoldPeriod(5)` 后滚动改进低于 `MinRollingImprovement` → 只打标（`champion flagged`），**默认仍保持冠军**——注意这里降级主要走 1 和 2，3 更多是告警。

> 对比旧文：旧文把 champion 的第三个出口写成较严格的"滚动改进 < DemotionThreshold(0.3) 直接降级"。真实代码里 `MinRollingImprovement` 是 **0.1**，且只在**超过任期**时用 `MaxChampionTenure` 那条路做硬降级；`DemotionThreshold=0.3` 用于 `shadow → demoted` 的成功率回退判断和 drop 反向下。请以本表为准。

### 5.4 demoted

- 再次 `MeetsPromotionCriteria` → 重升 shadow（re-promote）。
- 落败时间 ≥ `ChampionHoldPeriod*2`（10 代）→ retired。

## 6. Promote / Demote 与冷却期

`Promote` 决定目标状态（candidate→shadow, shadow→champion, demoted→shadow），校验 `CanPromoteTo` 与冷却期后执行 `transitionState`，捕获基线，升冠军时 `addToChampions(taskType, id)`。`Demote` 同理按 `CanDemoteTo` 走（candidate→retired, shadow→demoted, champion→demoted, demoted→retired），降级自 champion 时 `removeFromChampions`。

```go
func (p *DefaultPromoter) canTransition(info *StrategyInfo) bool {
    if info.GenerationCount == 0 { return true } // 新策略立即生效
    return info.GenerationCount >= p.criteria.CoolDownGenerations // 默认 3 代
}
```

## 7. 增长防护（#56，真实）

Promoter 有两条防无限增长的措施（对应 issue #56）：

```go
const (
    maxPromotionHistoryPerStrategy = 64              // 每条策略最多保留 64 条转移记录
    retiredRetention                = 24 * time.Hour  // Retired 策略保留 24h
)
```

`transitionState` 会截断每条策略的历史；`pruneRetiredLocked` 把 `Retired` 超过 `retiredRetention` 的策略连同历史一起删掉（否则 `strategies` 和 `history` 会随新 ID 无限增长）。`SetGeneration(g)` 推进代数并给所有策略 `GenerationCount++`。

## 8. 公开 API 一览

`api/evolution/evolution.go` 通过适配器暴露一个简化版：`NewPromoter(criteria)` 返回 `Promoter`，其 `Evaluate(ctx, strategyID, successRate, confidence)` 把只含成功率/置信度的证据包装成 `experience.Evidence`（`ErrorRate: 1-successRate`, `SampleCount: 1`）后转调内部 `DefaultPromoter.Evaluate`。
（注意公开版的 `SampleCount=1`——所以从公开 API 走，`evaluateCandidate` 的"10 样本"门槛基本不会触发；设计上公开路径主要用于手动 promote/demote/查看，真正的自动晋升走内部 `experience.Evidence`。）

## 9. 小结

| 机制 | 关键参数/触发 | 目的 |
|------|--------------|------|
| candidate→shadow | 10 样本 + 50% 成功率 | 低门槛入场，鼓励竞争 |
| shadow→champion | 五条达标 + 相对基线改进 ≥0.5 | 保证冠军质量 |
| champion 保持 | 滚动改进（窗口 3、阈值 0.1） | 防停滞 |
| 任期硬限制 | `MaxChampionTenure=20` | 防"安全但停滞"永久占位 |
| 降级保护 | `CoolDownGenerations=3` | 防状态震荡 |
| 智退 | 落败 ≥10 代 → retired | 释放资源 |
| 内存上界 | 历史 64 条 / Retired 保留 24h | 防无限增长 |

一句话：**适者生存，但不让胜者永居**——既给优秀策略足够展示期（保持 5 代），又用任期与滚动改进把它拉下来给新策略机会。
